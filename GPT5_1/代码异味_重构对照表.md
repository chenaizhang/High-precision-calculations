## 代码异味 -> 重构手段对照表（GPT5_1 版）

| 代码异味 | 旧 C++ 代码体现 | Rust 重构手段（本项目中的落地位置） |
| --- | --- | --- |
| **复用能力低 / 无统一接口** | 四则运算是散乱的全局函数：`add/sub/cheng/chu/compare/negation/...`，参数都是 `Node*`，没有围绕“一个高精度数”的统一抽象。 | 定义 `BigDecimal` 结构体（`src/lib.rs`），把符号、数字位与小数位封装在一起；运算以 `&self` 方法形式暴露：`add/sub/mul/div`，并额外提供 `LegacyFormat` 与 `to_string_legacy` 作为“兼容旧行为”的统一出口。 |
| **数据建模混乱（用每一位的正负表示符号）** | 负数的每一位都存负值，例如 `-12.3` 被存成 `-1 -> -2 -> -3`；符号判定依赖遍历链表（`ispositive/dayu0`），0 的符号不明确。 | 引入单独的 `Sign` 枚举和纯正数字位 `digits: Vec<u8>`（0..=9），符号与数值彻底分离；`BigDecimal::is_zero` 明确零值语义，`normalize` 中保证 `0` 总是 `+0`。 |
| **隐式副作用 / 破坏性读操作** | `compare(Node*& num1, Node*& num2)` 内部 `reverse` + 修改 `num1 = num1->next`，调用者的头指针被悄悄篡改；`neg_big/add/subforchu` 会在不明显的路径上改写入参链表内容。 | 所有核心 API 采用不可变借用 + 返回新值：如 `fn add(&self, other: &Self) -> Self`；比较与格式化仅在局部 `Vec<u8>` 上工作，不会修改 `BigDecimal` 自身状态。不再使用 `&mut` 或指针引用链表作为“输出参数”。 |
| **内存安全问题（裸指针 + 手写释放）** | 使用 `new Node` / `delete` 管理链表；`compare/delete0/subforchu` 中多点早退/指针重写，极易造成内存泄漏或 double free。 | 彻底弃用裸指针，改用 `Vec<u8>` 表示数字位；由 Rust 的所有权和生命周期管理内存，无需手写释放逻辑；算法只在安全容器和局部变量上操作。 |
| **性能陷阱（构造/运算复杂度高）** | `append` 每次从头走到尾插入新节点，构造 n 位数字为 `O(n^2)`；除法用“反复减法”模拟长除 `while(compare(...)!=-1) subforchu(...)`，大数性能极差。 | 使用 `Vec::push` 线性收集输入数字，`add_digits/sub_digits/mul_digits/div_digits` 在连续内存上进行整型运算：加减是线性时间，乘法是二维卷积，除法实现为基于商候选的标准长除法。整体复杂度从链表版接近 `O(n^2)` 降为更合理的 `O(n log n)`~`O(n^2)` 水平，且常数显著降低。 |
| **重复代码 / 超大函数** | `cheng` 和 `chu` 中针对正负号分成两大分支，主体逻辑几乎完全复制；`chu` 函数本身数百行，难以阅读与维护。 | 把“绝对值层面的算法”抽到独立函数：如 `mul_digits` 与 `div_digits`；符号处理用 `Sign::from_is_negative(left.sign != right.sign)` 一行集中完成；函数体保持在数十行以内，便于测试与推理。 |
| **魔法数字散落** | 代码中出现大量 `20`（除法小数位）、`7`（`toosmall` 阈值）、`9`（`print_2` 中小数打印/舍入控制），缺少注释说明。 | 在 `src/lib.rs` 顶部集中定义 `DIV_FRACTIONAL_DIGITS`, `LEGACY_ROUND_DIGITS`, `TOO_SMALL_PREFIX_DIGITS` 常量，并用文档注释说明其含义与来源；后续如需更改精度，只需修改常量即可。 |
| **命名混乱（中英混用，语义不清）** | 如 `cheng` (乘)、`chu` (除)、`dayu0` (大于 0)、`xiaoshudian` (小数点) 等拼音命名混杂在英文代码中。 | 采用统一的英文语义命名：`mul/div/is_too_small_divisor/scale/normalize` 等；旧函数名只体现在文档和注释里，便于维护者快速理解。 |
| **错误处理缺失 / 模糊** | 除以 0 或除数过小统一打印 `"ERROR"` 字符串；解析阶段几乎不做非法字符/多小数点校验。 | 在类型层面引入 `Error` 枚举区分 `Empty/InvalidChar/MultipleDecimalPoints/NoDigits/DivisionByZeroOrTooSmall`；`parse` 和 `div` 返回 `Result<_, Error>`；在 CLI 中仅在需要“兼容旧输出”时把 `DivisionByZeroOrTooSmall` 映射为 `"ERROR"`。 |
| **输出逻辑与业务逻辑耦合严重** | `print_1/print_2` 既控制千分位和小数点，又包含特定于业务的“最多 10 位小数 + 奇怪舍入”，与核心数值存储紧耦合。 | 把“规范输出”与“兼容旧输出”解耦：`to_string_with_grouping` 提供常规、易懂的格式化；`to_string_legacy(LegacyFormat)` 独立封装旧 C++ 行为（包括历史舍入 bug），便于在测试中锁死而不影响未来扩展。 |
