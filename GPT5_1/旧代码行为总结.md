## 旧 C++ 代码行为总结

### 1. 输入规范

- 操作符：`+` / `-` / `*` / `/`，逐次读入。
- 操作数为字符串，允许：
  - 首字符为 `-` 表示负数（不支持中间再出现 `-`）。
  - 任意位置的 `,` 作为千分位分隔符，在解析时**直接忽略**，不校验位置是否合法。
  - 一个 `.` 作为小数点，超过一个小数点会导致解析行为未定义（本次 Rust 版本显式报错）。
  - 其他字符一律视为非法。

### 2. 小数对齐与 scale 规则

- 加法/减法：
  - 先分别统计两数小数点后位数 `x1`, `x2`。
  - 取 `x = max(x1, x2)`，对小数位不足的一方在**字符串末尾补 0**，再转换为链表。
  - 运算时按整数处理，最后输出时认为结果有 `x` 位小数。
- 乘法：
  - 结果小数位数为 `x = x1 + x2`。
- 除法：
  - 内部会额外计算出 **20 位小数**（通过在被除数后补 20 个 0 再做整数长除），并在输出阶段结合“旧 `print_2` 逻辑”进行截断/近似四舍五入。

### 3. 去零与对齐规则

- 链表存储采用“低位在头（反转后）”的方式，运算前会调用 `reverse`。
- `delete0` 在**反转后的链表头部**删除多余的 0（相当于去掉高位多余的 0），同时根据删除个数调整小数位 `x`。
- 输出前通常会：
  - 先调用 `delete0` 清理高位 0；
  - 再 `reverse` 回原顺序；
  - 在整数末尾根据 `x` 再裁剪掉多余的尾部 0。
- 零值的符号在旧实现中较为混乱（通过判断是否存在正位/负位得出），Rust 版本统一为 `+0`。

### 4. 输出与舍入规则

- 加减输出使用 `print_1`：
  - 支持千分位 `,` 格式；
  - 小数部分按 `x` 位输出，不主动做四舍五入（更多是“截断 + 特殊格式”的行为）。
- 乘除输出使用 `print_2`：
  - 同样带千分位。
  - 每个小数段最多输出 **10 位小数**，内部通过变量 `c` 控制：
    - 小数点后的前 9 位直接输出；
    - 第 10 位作为“当前位”，第 11 位用于“是否进一”的判断；
    - 这一逻辑存在明显缺陷：只对“当前位 + 1”而不处理连锁进位，且在部分分支中会错误打印多位数字。
  - 当小数不够 10 位时，不会额外补 0。

### 5. 除法 `ERROR` 条件

- 函数 `toosmall` 用来判断除数是否“过小”，近似地把非常接近 0 的数字也视为非法：
  - 会反转链表，使高位在前；
  - 从最高位开始检查**最多 7 位**是否全部为 0；
  - 如果前 7 节点全为 0，则认为过小，直接输出 `ERROR`。
- 直观等价条件（忽略链表前导零）：
  - 若小数形式为 `0.0000000…d...`，且在小数点后前 7 位都是 0，而第 8 位才首次出现非 0，则视为“too small”。
  - 例如：
    - `0.0000001`：前 6 位为 0，第 7 位为 1 ⇒ **合法**；
    - `0.00000001`：前 7 位为 0，第 8 位非 0 ⇒ **ERROR**。
- Rust 版本在 `BigDecimal::is_too_small_divisor` 中用 `scale` 与 `digits` 的组合重建了这条规则，并在 `div` 中将其统一映射为 `Error::DivisionByZeroOrTooSmall`，对外仍打印 `ERROR`。

### 6. 旧实现中存在的潜在 bug / 不一致

1. **比较函数修改头指针，导致结构被破坏**
   - `compare(Node*& num1, Node*& num2)`：
     - 会调用 `reverse(num1)` / `reverse(num2)` 改变链表方向；
     - 为跳过前导 0，直接执行 `num1 = num1->next;` 等操作，由于参数是引用，调用者持有的头指针也被永久改写；
     - 后续 `clear(head)` 时会漏删那些被跳过的节点，造成 **内存泄漏与逻辑不一致**。
   - Rust 版本：
     - 不暴露链表/指针，而是用不可变借用 `&self` 和局部 `Vec<u8>`，比较操作完全无副作用。

2. **符号通过“每一位的正负”编码，0 的符号混乱**
   - 负数在链表中每一位都存负值（如 `-12.3` ⇒ `-1 -> -2 -> -3`），导致：
     - `ispositive` / `dayu0` 要遍历全部节点判断正负；
     - 0 会被看成“非正数”，部分分支（如乘除符号处理）变得非常绕；
     - 某些路径下 `negation` 没有成对调用，链表会保持“被翻转后的符号”，引入隐式状态。
   - Rust 版本：
     - 独立 `Sign` 枚举，`digits` 永远是 `0..=9`，0 统一视为 `+0`。

3. **空指针 / 越界访问风险**
   - `delete0(Node*& head, int x)` 默认 `head` 非空，直接访问 `head->num`；
   - `print_1/print_2` 在没有防御时直接输出 `temp->num`；
   - `subforchu` 在 `p != nullptr || q != nullptr` 条件下循环，却无条件写 `p->num`，当 `p == nullptr` 且 `q != nullptr` 时会崩溃。
   - Rust 版本：
     - 不暴露裸指针，全部通过 `Vec` 与索引访问，边界处有明确检查；
     - 通过单元测试验证典型边界情况。

4. **算法复杂度与性能问题**

   - `append` 每次从头走到尾插入新节点，构造 n 位数字为 `O(n^2)`；
   - `cheng` 中多次对中间结果 `reverse` 再补 0，放大常数；
   - `chu` 实现为“长除法 + 反复减法”，在位数稍大时性能急剧下降。
   - Rust 版本：
     - 用 `Vec<u8>` 线性存储，`push` 为摊还 `O(1)`；
     - 乘法用“卷积式”两重循环；
     - 除法实现为基于 `div_digits` 的整型长除，避免频繁创建/销毁链表。

5. **输出逻辑难以维护**

   - `print_1` / `print_2` 中 `i, j, c` 等状态变量混在一起，存在：
     - 千分位与小数点逻辑纠缠；
     - 小数截断与舍入规则难以重现；
     - 一处改动容易破坏另一处行为。
   - Rust 版本：
     - 将“规范输出”（`to_string_with_grouping`）与“老行为输出”（`to_string_legacy` + `LegacyFormat`）分离；
     - 旧行为中的怪异逻辑被封装在 `format_legacy_*` 中，通过单元测试锁定行为。
