## 迁移说明：从 C++ 链表到 Rust `BigDecimal`

### 1. 数据结构映射

- **C++：**
  - 使用 `struct Node { int num; Node* next; }` 单向链表存储每一位数字；
  - 链表方向会在不同阶段通过 `reverse` 频繁翻转：
    - 输入解析：高位在前；
    - 运算前：通过 `reverse` 把低位移到表头，便于手算式加减/乘除；
  - 符号直接体现在 `num` 的正负上（负数每一位都是负的）。
- **Rust：**
  - 使用 `BigDecimal` 统一承载一个高精度数：
    - `sign: Sign`：仅在这里记录正负；
    - `digits: Vec<u8>`：**大端**数组，高位在前，元素范围 `0..=9`；
    - `scale: i32`：小数位数；
  - 不再显式存储“链表结构”，而是利用 `Vec` 的连续存储：
    - 随机访问方便，实现 `add_digits/mul_digits/div_digits` 更自然；
    - `Vec::push` 避免了旧 `append` 的 `O(n^2)` 构造性能问题。

### 2. 所有权 / 借用 与 副作用控制

- **C++ 旧代码问题：**
  - 函数参数大量使用 `Node*&`，例如 `compare(Node*& num1, Node*& num2)`：
    - 内部会 `reverse` 链表并修改 `num1 = num1->next` 跳过前导 0；
    - 调用者传入的头指针被悄然改写，后续释放和逻辑处理都受到影响；
  - 许多函数（`add/subforchu/neg_big` 等）会在内部调用 `negation` 修改输入链表的符号，却未必恢复原状。
- **Rust 重构策略：**
  - 对外 API 基本都采用不可变借用：`fn add(&self, other: &Self) -> Self` 等；
  - 算法内部若需要临时修改，则在局部克隆 `Vec<u8>` 或构造新的中间结果；
  - 比较、格式化等纯计算函数完全不影响原始 `BigDecimal`；
  - 通过 Rust 的所有权模型确保：
    - 任何可见的状态变化都体现在返回值或 `&mut self` 上；
    - 不存在“看似只读、实则修改”的隐藏副作用。

### 3. 不变量与类型系统的约束

核心不变量通过 `BigDecimal` 与辅助函数强制维护：

- `digits` 始终是 **0..=9 的大端序列**，不携带符号信息；
- `normalize` 保证：
  - `digits` 没有多余前导 0（除非值本身为 0）；
  - 若值为 0，则 `sign` 被强制为 `Positive`，`scale = 0`；
- `scale` 表示小数位数，逻辑上应为非负：
  - 仅在中间计算（例如除法）中可能出现负数；
  - 通过 `normalized_for_ops` 把 `scale < 0` 的情况展开为 `scale >= 0` 的标准形式再参与后续运算；
- 除法中的“过小除数”条件被封装为 `is_too_small_divisor`：
  - 根据 `scale` 与 `digits` 推导出与旧 `toosmall` 等价的判定；
  - 这种规则只在 `div` 内部调用，对外统一表现为 `Error::DivisionByZeroOrTooSmall`。

### 4. 算法映射与优化

1. **加法 / 减法**
   - 旧代码：依赖链表反转 + 进位/借位，且因符号编码在每一位中，条件分支较复杂。
   - 新实现：
     - 先通过 `align_scales` 对齐两数小数位（在 `digits` 尾部补 0）；
     - 根据符号选择 `add_digits` 或 `sub_digits`，并用 `cmp_digits` 决定结果符号；
     - 算法退化为常规多精度整数加减，易于验证正确性。

2. **乘法**
   - 旧代码：双重循环 + 反复 `reverse(tempresult)` + 补 0，存在大量多余的反转和拷贝；
   - 新实现：
     - 在大端 `digits` 上实现标准卷积式乘法（累加到 `u32` 累加器数组，再统一处理进位）；
     - 结果小数位数为 `self.scale + other.scale`，再通过 `normalize` 去掉高位多余 0。

3. **除法**
   - 旧代码：长除法 + `while(compare(...)!=-1) subforchu(...)` 的反复减法，性能和可读性都较差；
   - 新实现：
     - 先调用 `is_too_small_divisor` 复刻 `toosmall` 的 ERROR 逻辑；
     - 将被除数 `digits` 在末尾补上 `DIV_FRACTIONAL_DIGITS` 个 0，再调用 `div_digits` 执行整型长除；
     - `div_digits` 使用“候选商 1..9 反推”的写法，复杂度远优于反复减法；
     - 最终结果小数位数为 `DIV_FRACTIONAL_DIGITS + left.scale - right.scale`，并交由 `normalize` 清理。

### 5. 格式化与旧行为复刻

- **C++：**
  - `print_1`：用于加减，逻辑混合了整数/小数输出与千分位插入；
  - `print_2`：用于乘除，在 `print_1` 基础上加入了复杂的 `c` 计数器控制和近似四舍五入逻辑（带有历史缺陷）。
- **Rust：**
  - 将格式化拆分为两个层次：
    1. `to_string_with_grouping(grouping: bool)`：面向通用复用的规范输出（不刻意复刻 C++ 的 bug）；
    2. `to_string_legacy(mode: LegacyFormat)`：
       - `LegacyFormat::AddSub` ⇒ 对应 `print_1` 行为；
       - `LegacyFormat::MulDiv` ⇒ 对应 `print_2` 行为，其中：
         - 通过常量 `LEGACY_ROUND_DIGITS` 控制小数位打印 + 舍入判定；
         - 严格按照旧代码流程模拟 `c` 的变化和决策分支，使已有测试用例可以一一对照。

### 6. CLI 接口与兼容性

- Rust 版 `src/main.rs` 保持与 C++ `main.cpp` 相同的交互文案和输入流程：
  - 先读入次数 `n`；
  - 每次依次读入操作符、左操作数、右操作数；
  - 对于 `/` 操作，当 `div` 返回 `Err(Error::DivisionByZeroOrTooSmall)` 时打印 `"ERROR"`，其它错误也统一降级为 `"ERROR"`，与旧程序的用户可见行为保持一致。
- 这样既保留了旧系统的输入/输出约定，又在库层引入了更精细的错误信息，便于后续在不破坏 CLI 行为的前提下开发新的使用场景（例如直接在别的 Rust 项目中复用 `BigDecimal`）。
