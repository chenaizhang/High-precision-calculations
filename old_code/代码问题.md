这段代码本质上是在“手写大数/高精度小数四则运算”：把输入字符串（可能含 `-`、`,` 千分位、`.` 小数点）拆成**按位存储的链表**，再用“竖式”实现 `+ - * /`，最后再格式化输出。

但它为了省事，把**符号**直接塞进“每一位数字”的正负号里（负数就把每一位都存成负的），再靠大量 `reverse / negation / compare / delete0` 来补救——这会带来很多典型代码异味和真实 bug 风险。

---

## 这份代码的主要问题（按严重程度）

### 1) **隐式副作用极多：函数会偷偷改参数/改链表结构**

这是最致命的“异味 + bug 温床”。

- `compare(Node*& num1, Node*& num2)`
  表面是比较大小，实际上它：
  1. **反转链表**（两次）
  2. 为跳过前导 0，直接 `num1 = num1->next;`、`num2 = num2->next;`
     由于参数是 `Node*&`，这会把调用者的头指针也一起改掉——**调用者再也拿不回那些被跳过的节点**，后续 `clear(head)` 会漏删、造成**内存泄漏**，甚至逻辑错乱。
- `neg_big` / `add` 会对传入链表直接 `negation()`（把所有位取反），而且不总是恢复原状。
  这类“把输入当临时变量”的写法，迁移到别的语言（Java/Python）时也非常容易翻车。

> 异味标签：**Unexpected Side Effects / Action at a Distance / 破坏性读操作**

---

### 2) **数据建模有根本缺陷：用“每一位数字的正负”表示符号**

负数链表里每一位都是负的：`-1 -2 -3 ...`。这会导致：

- “判断符号”居然要遍历所有位：`ispositive()`、`dayu0()`
- 0 的符号很尴尬：`dayu0()` 用“是否存在 >0 的位”判断正数，**0 会被当成“非正”**，很多符号分支会变得不自然。
- `add()` 里为了处理符号混合，写了非常绕的条件判断 + 递归调用自己，还在里面改输入号位：可读性差、可验证性差。

> 异味标签：**Primitive Obsession（用 int 正负承载语义）/ 违反不变量 / 复杂条件逻辑**

更健康的模型应该是：
**sign（±）单独存** + **digits 全部是 0..9** + **scale（小数位数）单独存**。

---

### 3) **空指针/越界风险很现实**

- `delete0(Node*& head, int x)`：直接用 `head->num`，如果 `head == nullptr` 就崩。
- `print_1/print_2`：默认 `head` 非空，直接 `std::cout<<temp->num;`。
- `subforchu`：循环条件是 `p != nullptr || q != nullptr`，但循环里无条件写 `p->num = (sum % 10);`
  一旦 `p == nullptr` 而 `q != nullptr`，**直接空指针解引用**。

> 异味标签：**缺少输入/状态校验 / 不安全指针使用**

---

### 4) **算法复杂度很差：大量 O(n²)/更糟**

- `append()` 每次都从头走到尾，构造 n 位数字是 **O(n²)**。
- `cheng()` 里每一位乘法的部分结果还会多次 `reverse(tempresult)` 来“补 0”，进一步放大常数。
- `chu()` 用“反复减法”做除法：
  `while (compare(head1, head2) != -1) subforchu(...)`
  这是最慢的那种除法实现，数稍微大一点会卡到不可用。

> 异味标签：**Performance Trap / 重复遍历 / 低效数据结构选择**

### 6) **魔法数字、命名混乱**

- `20`：除法固定算 20 位小数
- `7`：`toosmall()` 只检查“前 7 位是否全 0”来判断是否 ERROR（这甚至不是“除数为 0”的正确判断）
- `9`：`print_2` 用 `c=9` 做输出位数/四舍五入逻辑，非常脆弱

命名也混合拼音/英语、语义不清：`dayu0 / cheng / chu / tuiwei / toosmall`。

> 异味标签：**Magic Numbers / Poor Naming / Low Readability**

### 7) **复用能力低：面向过程、缺少统一接口与抽象边界**

这份代码把“一个高精度数”拆成了大量全局函数 + 裸 `Node*` 在各处传来传去，导致：

- **没有统一数据类型接口**：
  没有 `BigNumber`/`BigDecimal` 这样的抽象；任何函数都可以随意 `reverse/negation/append` 改内部结构，靠“调用顺序约定”维持正确性。
  一旦你想复用其中某个能力（比如只要 `add`），你就必须把一堆依赖函数一起搬走（`compare/ispositive/neg_big/reverse/delete0/...`）。
- **没有稳定不变量（contract）**：
  比如“链表是高位在前还是低位在前”“每一位是否允许为负”“是否允许前导 0”“小数位数如何存”，全靠上下文隐含。
  这会让维护者/LLM 在迁移时很难判断：某个函数希望输入是“反转后的链表”还是“原序链表”。
- **职责混杂，模块边界缺失**：
  解析输入（去逗号/小数点/符号）、数值对齐（补 0）、运算、输出格式化（千分位/四舍五入）全部散落在 `main` 和多个函数中。
  这种结构几乎无法“替换实现”（例如把链表实现换成 vector、把除法精度从 20 改成可配置）而不牵一发动全身。

> 异味标签：**Missing Abstraction / Low Cohesion / Tight Coupling / Shotgun Surgery / Non-uniform Interface**
