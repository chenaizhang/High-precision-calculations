# 代码异味 -> 重构手段对照表

| 代码异味 (Code Smell) | 旧 C++ 代码体现 | Rust 重构手段 |
| :--- | :--- | :--- |
| **复用能力低 / 无统一接口** | 散乱的全局函数 `add`, `sub`, `cheng`, `chu`，参数不统一。 | 定义 `BigDecimal` 结构体，实现 `Add`, `Sub`, `Mul`, `Div` trait，提供统一方法调用。 |
| **数据结构低效** | 使用单向链表 `struct Node` 存储每一位，空间碎片化且不连续。 | 使用 `Vec<u8>` 存储数字位，内存连续，缓存友好，支持随机访问。 |
| **性能陷阱** | `append` 函数每次从头遍历到尾部插入，复杂度 $O(N^2)$。 | `Vec::push` 尾部插入，$O(1)$ 均摊复杂度；解析时直接收集。 |
| **隐式副作用** | `compare(Node*& num1, ...)` 内部调用 `reverse` 修改了链表方向，外部调用者不知情。 | Rust 所有权系统强制明确借用规则。`add(&self, other)` 不修改 `self`，返回新实例。 |
| **内存管理风险** | 手动 `new Node` / `delete`，`delete0` 逻辑复杂，容易泄漏或 Double Free。 | 利用 Rust 的 RAII（资源获取即初始化），`Vec` 自动管理内存，无裸指针。 |
| **代码重复** | `chu` 函数中正负数处理逻辑几乎完全复制粘贴了两遍。 | 提取核心算法 `div_rem_abs`（仅处理绝对值），符号逻辑在 `checked_div` 中统一处理。 |
| **魔法数字** | 散落在代码中的 `20`（除法精度）、`7`（`toosmall` 阈值）。 | 将除法精度逻辑封装在计算过程中，清晰定义精度规则（如 `20 + scale_diff`）。 |
| **命名混乱** | `cheng` (乘), `chu` (除), `dayu0` (大于0), `xiaoshudian` (小数点)。 | 使用标准的英文命名：`mul`, `div`, `is_positive`, `scale`。 |
| **错误处理缺失** | 除以零仅输出 "ERROR" 字符串，或者通过 `toosmall` 模糊判断。 | 返回 `Result<BigDecimal, BigIntError>`，明确区分 `ParseError` 和 `DivisionByZero`。 |
