# 旧代码行为总结

## 1. 输入规范

- **格式**：字符串输入。
- **支持字符**：数字 `0-9`，负号 `-`（仅在首位），小数点 `.`，千分位分隔符 `,`（会被忽略）。
- **示例**：`1,234.56`，`-0.005`。

## 2. 运算行为规则

### 加法 (+) / 减法 (-)

- **对齐规则**：自动补齐小数位，以两个操作数中较长的小数位数为准。
- **精度**：结果的小数位数 = `max(scale1, scale2)`。
- **去零规则**：运算后会去除小数部分末尾的 0（`delete0` 逻辑），以及整数部分的前导 0。

### 乘法 (\*)

- **精度**：结果的小数位数 = `scale1 + scale2`。
- **舍入**：旧代码在输出时（`print_2`）似乎有基于剩余位数的舍入或截断逻辑，Rust 实现中统一采用“计算多一位用于四舍五入”的策略。

### 除法 (/)

- **精度**：目标小数位数约为 `20 + scale1 - scale2`。实际上是保证了约 20 位的有效小数精度。
- **算法**：旧代码使用“减法模拟除法”（`subforchu`），效率极低。
- **舍入**：计算额外的位数用于最后一位的四舍五入。

## 3. 旧代码潜在问题与 Bug

1.  **副作用严重**：`compare`、`add` 等函数会修改传入的链表指针（如 `reverse`），导致后续使用时链表顺序混乱。
2.  **内存泄漏**：手动 `new` 和 `delete`，且 `delete0` 等函数在移除节点时逻辑复杂，容易造成内存泄漏。
3.  **性能陷阱**：
    - `append` 操作需要遍历链表尾部，导致构建链表复杂度为 $O(N^2)$。
    - 除法使用重复减法，当被除数远大于除数时，性能极差。
4.  **魔法数字**：除法中硬编码了 `20` 作为精度控制，`print_2` 中有 `c=9` 等不明含义的限制。

## 4. Rust 复刻策略

- **行为一致性**：保持了输入解析忽略 `,` 的逻辑，保持了 `+` `-` `*` `/` 的精度计算规则。
- **改进**：
  - 除法改用“长除法”算法，大幅提升性能。
  - 消除了副作用，所有运算返回新实例，不修改原数据。
  - 内存安全，无裸指针。

## 5. 运行方式

### 交互式运行

```bash
cd Trae
cargo run
```

在输入完所有数据后输入 EOF 终止输入流。

### 运行 1,000,000 条数据，测试 10 次，记录平均用时

```bash
cargo build --release

: > time.txt  # 清空 time.txt

for i in {1..10}; do
  echo "run $i" >> time.txt
  /usr/bin/time -p ./target/release/high_precision_calculations \
    < ../llm_crosslang_test_input_1000000.txt > /dev/null 2>> time.txt
done

awk '
  $1=="real"{r+=$2; rc++}
  $1=="user"{u+=$2; uc++}
  $1=="sys" {s+=$2; sc++}
  END{
    printf("avg_real %.6f\n", r/rc);
    printf("avg_user %.6f\n", u/uc);
    printf("avg_sys  %.6f\n", s/sc);
  }' time.txt | tee time_avg.txt
```

#### 示例返回位于`time_avg.txt`

```txt
avg_real 2.214000 // 墙钟时间（从开始到结束你实际等了多久）
avg_user 1.815000 // CPU 在用户态执行你程序代码的时间（算法、循环、计算）
avg_sys  0.393000 // CPU 在内核态花的时间（系统调用/IO/内存分配/释放/页缓存等）
```
